# 雲端掃描與追蹤

「完整掃描」和「每六小時追蹤」是不同工作。原有 daily-tw.yml 負責收盤資料及報告；market-radar.yml 負責市場雷達和可續跑的財報補件。成功退出不代表全市場缺值全部補齊，必須查看 scanned、eligible、verified、pending。

radar-monitor.yml 在上述工作結束後檢查結果，另於 UTC 01:41、07:41、13:41、19:41（台灣 09:41、15:41、21:41、03:41）做六小時檢查。GitHub 排程可能延遲。監控不啟動、取消或修改掃描，補件仍沿用原排程。

首次接手通知既有 Telegram；之後只通知異常狀態改變／恢復、可核實範圍補齊、或財報核實筆數連續 48 小時無進展。不重送日常報告。檢查包含來源健康、快照超過 48 小時、工作漏跑（雷達 48 小時／平日收盤工作 96 小時）、執行或排隊超過 8 小時、既有 Telegram 回執與不明送達。它不是逐筆通知完整性稽核，也不保證每筆應發訊息都有回執。

公開診斷和獨立的通知回執保存在 Actions artifacts；不包含 Token、Chat ID、持股或交易指令。讀取的市場 SQLite 只是下載副本，從不回寫到原市場 artifact。監控序列執行，通知不明時不自動重送；請核對 Actions 與 Telegram 後人工處理。

如監控本身或 GitHub 停機，依靠 GitHub Actions 失敗通知及人工查看；不能靠同一個停機平台自我保證告警。90 天監控 artifact 保存期過後，首次接手基準會重建。可在 Actions 手動執行，send=false 只驗證，send=true 啟用實際通知。乾跑不推進已通知狀態。

這次取代本機的是檢查與通知；不配置雲端 AI 自動改碼、開 PR、合併或下單。需要修正時通知人工處理。確認雲端 send=true 執行成功且回執保存後，才暫停本機「台股 Radar 補件與運作追蹤」。
